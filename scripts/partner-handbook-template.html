1. Executive Summary & Problem Statement

QuickCourt is a high-performance web platform designed to digitize and elevate recreational sports turf and leisure facility bookings. Traditional sports venues across urban centers rely heavily on unorganized paper diaries, fragmented phone calls, and manual WhatsApp messaging. This archaic process results in three chronic operational failures:

1. Double-Booking Catastrophes

Without atomic reservation locks, venues routinely promise the same 7:00 PM court to two separate groups, causing heated arguments on site.

2. Payment & Booking Friction

Unclear hourly pricing, confusing weekend surges, and clunky UPI screenshots create awkward split-payment delays among friends.

3. Disjointed Amenities

Players finish intense 60-minute games only to stand in long lines for water, protein shakes, or discover the cafe is sold out.

QuickCourt solves this entirely by delivering a single, synchronized platform that unites real-time turf reservations, Go-Kart racing heat management, synchronized food court pre-orders, and a gamified loyalty currency (1 Court Coin = ₹1).

4. Go-Karting, Food Pre-Order & Gamification Mechanics

🏎️ Go-Karting & Motor Racing Engine

Integrated into the booking engine is a specialized module for racing circuits (e.g. Velocity Circuit). It implements strict safety rules and timing transponder support:

Cadet Class (6.5 HP): Speed governed to 40 km/h. Suitable for junior drivers (ages 10-14).
Pro Twin-Engine (13 HP): Top speed 75 km/h. High-grip slicks and hydraulic disc braking.
Heat Concurrency Guard: Automatically caps active karts to 8 per heat to prevent track collisions.

🥤 CourtSide Cafe: Pre-Order Synchronization

QuickCourt links food prep times to court slot bookings. If a player books a 7:00 PM – 8:00 PM match, their ordered smoothies and electrolyte waters are scheduled for preparation at 7:50 PM.

Pickup Workflow: Players walk off court directly to the CourtSide counter. They display their booking reference ID (e.g., QC-2026-1P7SUA2D) or scan their digital QR pass. No cash exchange or card swiping is required at the counter.

🪙 Court Coins & Double-Entry Wallet Ledger

Unlike obfuscated point systems, QuickCourt uses a direct financial peg: 1 Court Coin = ₹1 INR.

10% Earn Rate: Every finished booking credits 10% of the court fee in coins directly to the user's wallet.
Instant Checkout Discount: Coins can be redeemed with a 1-tap slider. 50 coins = ₹50 deducted immediately.
Digital Scratch Cards: Completed weekend games award a digital scratch card with surprise bonuses (10–100 coins).

5. Step-by-Step Technical Workflows & Concurrency

5.1 Concurrency & Double-Booking Prevention

To prevent two users from booking the exact same court and slot simultaneously, the booking endpoint uses Prisma's atomic interactive transactions (prisma.$transaction): 

// Atomic Double-Booking Validation in /api/bookings/route.ts
const result = await prisma.$transaction(async (tx) => {
  // 1. Check if slot is already booked
  const existingBooking = await tx.booking.findFirst({
    where: { courtId, date, startTime, status: { not: 'CANCELLED' } }
  });
  if (existingBooking) throw new Error("SLOT_ALREADY_BOOKED");

  // 2. Check if venue owner blocked the slot
  const isBlocked = await tx.blockedSlot.findFirst({
    where: { courtId, date, startTime }
  });
  if (isBlocked) throw new Error("SLOT_BLOCKED_BY_OWNER");

  // 3. Atomically create the booking & deduct coins
  const booking = await tx.booking.create({ data: { ... } });
  if (coinsRedeemed > 0) {
    await tx.wallet.update({ where: { userId }, data: { balance: { decrement: coinsRedeemed } } });
    await tx.coinTransaction.create({ data: { type: 'REDEEMED', amount: coinsRedeemed, ... } });
  }
  return booking;
});

5.2 Authentication & Session Lifecycle

Authentication is fully stateless and secured via HTTP-only cookies. When a user logs in:

  1. The credentials are verified against the Supabase PostgreSQL database using bcryptjs.compare().
  2. A signed JWT is issued with a 7-day expiration containing the user's ID, role, and email.
  3. The token is stored in a secure cookie named qc_token with httpOnly: true, sameSite: 'lax', path: '/'.
  4. On every page transition, Next.js Edge Middleware intercepts the request, validates the token signature, and enforces RBAC guards before any HTML is rendered.

7. REST API Specifications Catalog

All endpoints return standard JSON payloads with HTTP status codes (200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 409 Conflict):

Endpoint Method Auth Payload / Parameters Description
/api/auth/login POST Public { email, password } Validates credentials, sets HTTP-only qc_token cookie.
/api/auth/session GET Cookie None Returns current user session, initials, and role.
/api/facilities GET Public ?sport=&city=&search= Lists active sports venues with courts and pricing.
/api/courts/:id/slots GET Public ?date=YYYY-MM-DD Returns slot schedule with availability flags.
/api/bookings POST Player { courtId, date, startTime, coinsRedeemed, foodItems } Executes atomic booking reservation lock.
/api/bookings/my GET Player None Retrieves active and past booking passes for user.
/api/owner/blocked-slots POST Owner { courtId, date, startTime, reason } Locks court slot for maintenance or weather.
/api/wallet GET Player None Returns live Court Coin balance and transaction ledger.

10. Recent Engineering Fixes, RCA & Future Roadmap

RCA: 401 Session Sync & Header Initials Badge

Symptom: The browser console previously logged Failed to load resource: /api/auth/login status 401, and the header displayed "Log in / Join the club" buttons even when the screen greeted "Game on, rk".

Root Cause: Two concurrent issues: (1) Default dummy credentials in the client state didn't exist in the freshly migrated database until seeded, and (2) src/components/QuickCourtApp.tsx contained hardcoded desktop header action buttons that failed to read the authenticated session state.

Resolution: Seeded all standard test accounts with hashed passwords via prisma:seed and updated QuickCourtApp.tsx with dynamic authenticated user badge avatars, initials display (e.g. rk), role badges, and an interactive dropdown logout menu.
